# `@enardo/http` becomes `@enardo/http-client`

## Why

The first item of the backlog, from decision 9 of the spec of `feature/http/client-errors` (2026-10-05). The package only makes requests, but its name and its description ("HTTP client over the Fetch API, for browser apps and Node servers") read as client and server: at checkpoint 1 of that branch, they did. Renaming it now touches a single consumer, `@cambusa/web`, and lets the three queued `@enardo/http` branches start with the new scope.

Nothing else changes: the exports (`HttpClient`, `HttpResponseError`, `NetworkError` and the types) already say "client", and no test names the package.

Probes ran on `master` (`e0629a3`), in a clone of the repo inside a throwaway container from the dev image. The real `node_modules` were not touched.

## Changes

### 1. The package, its folder, the consumer

| File | Today | After |
| --- | --- | --- |
| `packages/http/` | the folder | `packages/http-client/`, moved with `git mv` |
| its `package.json` | `"name": "@enardo/http"` | `"name": "@enardo/http-client"` |
| `projects/cambusa/apps/web/package.json` | `"@enardo/http": "workspace:*"` | `"@enardo/http-client": "workspace:*"` |
| `projects/cambusa/apps/web/src/lib/api/http.ts` | `import { HttpClient } from "@enardo/http"` | `from "@enardo/http-client"` |
| `pnpm-lock.yaml` | | regenerated by `pnpm install` |

Probed:

- **`git mv` moves the folder with what it ignores.** A marker file in `packages/http/node_modules/` ended up in `packages/http-client/node_modules/`, and `packages/http/` was gone. So the package's `node_modules` and `dist` move along.
- **The lockfile diff holds the two renames and nothing else.** `pnpm install --lockfile-only` after the three edits above changed only:
  - the importer key `packages/http:` → `packages/http-client:`;
  - in the `projects/cambusa/apps/web` importer, `'@enardo/http'` → `'@enardo/http-client'`, and `link:../../../../packages/http` → `link:../../../../packages/http-client`.
- **With the code edits alone, `pnpm verify` checks the renamed package and its consumer, and nothing more** (**amended after review**: the docs widen it, see verification 1). On the clone, with the rename committed on a branch, `turbo run format:check lint typecheck test --filter='...[master]' --dry=json` listed the four tasks for `@enardo/http-client` and `@cambusa/web` only; every other package showed up only for `build`, as a dependency. The deleted `packages/http/` paths do not widen the set. On `master` itself the set is empty.

Not probed: the real `node_modules` after the move. `pnpm install` in the dev container has to replace `web/node_modules/@enardo/http` with `@enardo/http-client`; verification 2 checks it.

### 2. The description

`package.json` and the first line of the package's `CLAUDE.md` say what the package does, in the package's own words ("browser/Node" for the runtimes, and the caller's role only):

- `package.json`: `"HTTP client over the Fetch API, for browser apps and Node servers"` → `"HTTP client over the Fetch API: makes requests, in browsers and on Node"`;
- `CLAUDE.md`: "HTTP client over the Fetch API, for browser apps and Node servers alike." → "HTTP client over the Fetch API: it makes requests, in browsers and on Node alike." The rest of the paragraph already says what a Node consumer is: "a server calling upstream services".

The README's opening already says it ("it only makes requests … Receiving requests is the server framework's job"), and stays.

### 3. The docs that describe the package as it is

From `git grep -E '@enardo/http([^-a-z]|$)|packages/http([^-a-z]|$)'`, every reference to the package as it is today takes the new name:

- `packages/http-client/README.md`: the title, the two `import` examples, "Import the errors from `@enardo/http`", "Run these inside `packages/http`";
- `packages/http-client/CLAUDE.md`: the title;
- `packages/errors/README.md` (twice) and `packages/errors/CLAUDE.md`: the package that replaced the HTTP classes;

  - the scope of the three queued branches: `fix/http-client/redact-cause`, `fix/http-client/base-url` (also where `fix/http-client/redact-cause` names it), `feature/http-client/timeouts-and-abort`;
  - the package's name where an item describes the package as it is: the `cause` item, ts-rest, the presets' `lib`, the runtime checks, `@types/node`, the logger split (`http` → `http-client` in its list of packages), the `/// <reference>`, the error body, `GET` with a body.

### 4. What keeps the old name

Records of the past keep the names they had (decision 1):

- `docs/specs/`: frozen after merge;
- `docs/adr/0003-type-guards-claim-only-what-they-check.md`: an accepted ADR is never edited;
- the names of merged branches (`feature/http/client-errors`, `fix/http/runtime-neutral-types`, …) in the root `CLAUDE.md`, in `docs/backlog.md`, and in the comments of `__tests__/index.test.ts`;
- the path `packages/http/node_modules/@types/node` in the root `CLAUDE.md`, in the lesson about `feature/http/client-errors`: it tells what happened in that branch;
- "the architectural review of `@enardo/http` (2026-09-25)", the source of three queued items and two items to evaluate;
- the comment "An upstream failure as HttpClient of @enardo/http builds it" in the api-server's `error-handler.middleware.test.ts` (decision 2).

## Decisions (to confirm at checkpoint 1)

1. **Current truth takes the new name, records keep the old one.** A spec, an ADR, a merged branch's name and the name of a past review say what happened, under the name it had then. A README, a `CLAUDE.md` or a backlog item says what is, and changes. After this branch, the `git grep` of verification 5 finds the records of §4, and nothing else. **Amended after review**: the spec first gave `git grep '@enardo/http\b'`, which also matches `@enardo/http-client` and `@enardo/http-status`, since `\b` falls before the hyphen.
2. **The api-server's test comment stays.** It describes what `HttpClient` built before `feature/http/client-errors`, so it is already wrong, and the queued `refactor/errors/drop-http-errors` names it as a comment to fix when it removes the HTTP classes. Renaming the package inside a wrong sentence would not make it right, and this refactor changes no test.
3. **No new test, and no `test-author` run.** No behavior changes and no test names the package. That the consumer resolves the new name and no longer the old one is checked by `@cambusa/web`'s typecheck and build: its import is the only one.
4. **Three commits after the spec**: the rename with its docs (§1 and §3 except the backlog), which has to be atomic to stay green; the description (§2), a separate logical change; the backlog (§3), in a `[repo]` commit like every backlog change. The rename commit takes the new scope, `[@enardo/http-client]`: the consumer and the docs follow the package.
