# Move `@enardo/password-hasher-bcrypt` to `bcrypt` 6

## Why

`@enardo/password-hasher-bcrypt` takes `bcrypt` `^5.1.1` as a peer, so every app that runs it installs `bcrypt>@mapbox/node-pre-gyp>tar` 6.2.1 and `node-pre-gyp`'s `rimraf>glob>minimatch>brace-expansion` 1.1.18: one critical, ten high and four moderate advisories, which no refresh within `bcrypt` 5 closes. `bcrypt` 6 drops `node-pre-gyp`. The advisories leave an app when it moves its own `bcrypt` to 6, which the adapter's peer range asks for: pnpm only warns on an unmet peer (ADR 0013). From the first *Queued* item of `docs/backlog.md`, found by the intake of a backlog choice (2026-10-23).

## Probes

- `pnpm audit --json` on `main`, in the dev container → 15 advisories, every one on a path `packages__password-hasher-bcrypt>bcrypt>@mapbox/node-pre-gyp>…`: `tar` (12, `patched_versions` from `>=7.5.8` to `>=7.5.21`, the critical `GHSA-23hp-3jrh-7fpw` `>=7.5.19`) and `brace-expansion` (3, up to `>=1.1.21`). `bcrypt` is the only route to either.
- `npm view bcrypt@6`, throwaway container → 6.0.0, the latest, published 2025-05-11; `dependencies`: `node-addon-api` `^8.3.0`, `node-gyp-build` `^4.8.4`; `engines.node` `>= 18`; no `types`.
- `npm i bcrypt@6.0.0` + `npm ls --all` + `npm audit`, throwaway container → three packages (`bcrypt`, `node-addon-api` 8.9.2, `node-gyp-build` 4.8.4), `found 0 vulnerabilities`.
- `bcrypt` 6 install → its `install` script is `node-gyp-build`, which finds a prebuild: `prebuilds/` holds `linux-x64/bcrypt.glibc.node` and `bcrypt.musl.node`, also `linux-arm64`, `linux-arm`, `darwin-*`, `win32-*`. With `--ignore-scripts` it still loads (no `build/`). It installs and hashes on `node:24-alpine` too.
- pnpm 11.28.6, throwaway workspace of two packages that import `bcrypt` 6.0.0 → without `allowBuilds`, `ERR_PNPM_IGNORED_BUILDS: Ignored build scripts: bcrypt@6.0.0`; with `allowBuilds: bcrypt: true` (what `pnpm-workspace.yaml:4` holds) it runs `node-gyp-build` and `pnpm audit` says `No known vulnerabilities found`.
- `bcrypt` 5.1.1 and 6.0.0 side by side (npm aliases), throwaway container:
  - both hash with the `$2b$` prefix; 6 verifies a hash of 5, 5 one of 6, and 6 a hash of 5 rewritten as `$2a$` → `true` each;
  - 6 reads the 72nd byte (`"a"×71 + "X"` vs `+ "Y"` → `false`), ignores what follows it counted in UTF-8 (`"é"×36 + "Y"` vs `"é"×36` → `true`), and hashes 200 bytes without throwing;
  - 6 encodes a lone surrogate as U+FFFD: a hash of `"pw\uD800"` matches `"pw\uDC00"` and `"pw�"`; so does a hash of `"pw\uD800"` made by 5, compared by 6 with `"pw�"`;
  - `compare` with a hash that is not one, an empty hash, or an empty password → `false` on both; `undefined` and a number throw the same messages on both;
  - `saltRounds` 0, 3, 4.5 → `$2b$10$`, `$2b$04$`, `$2b$04$` on both; `"5"` throws `Invalid salt` on both.
- `@types/bcrypt` 5.0.2 vs 6.0.0 (published 2025-07-19), `npm pack` → `index.d.ts` identical; 6.0.0 depends on `@types/node` `*`.

Cases 1–3 run on both 5.1.1 and 6.0.0 → the outcomes they expect, on each.

## Decisions

- **The peer range is `^6.0.0`**, a new major of the adapter: 3.0.0. Taken with the user at intake. After this branch the tests run only `bcrypt` 6, and a peer range claims only the versions the tests run; an app changes the adapter's specifier in the same edit as its `bcrypt`. Not taken: `^5.1.1 || ^6.0.0`, a minor that breaks no app, but declares a support for `bcrypt` 5 that no test runs any more. Neither range moves an app off `bcrypt` 5 by itself: the app's own bump does.
- **`@types/bcrypt` moves to `^6.0.0`**, the major that matches: its declarations are those of 5.0.2.
- **`allowBuilds: bcrypt: true` stays**: pnpm 11 refuses an install with an ignored build, and the prebuild makes the script fast. Setting it to `false` would also load, but is a choice for each app, not this branch.

## Test cases

In `__tests__/bcrypt.password-hasher.test.ts`, beside the existing four, which stay unchanged and green:

1. `compare("P@ssword123", "$2b$04$K3jkotAxEI6VAxGGMsYVBua0nImI9fCxSsOQhpjcvi0DKZ/zmbUWS")`, a hash made by `bcrypt` 5.1.1 → `true`: a hash an app stored before the upgrade still verifies.
2. `compare("P@ssword124", <the same hash>)` → `false`: case 1 does not pass because `compare` accepts any password against that hash.
3. `compare("pw�", "$2b$04$kK3eX./9Zx/qFKapeVPk6OxnUqXaw4E6UZbxZ3lpE0Er0w0OFb2Em")`, the hash of `"pw\uD800"` made by `bcrypt` 5.1.1 → `true`; and `compare("pw\uDC00", <the same hash>)` → `true`; and `compare("pw", <the same hash>)` → `false`, so that the match is the U+FFFD, not a dropped character. The README documents it, and a test now pins it.

The comment above the 72-byte cases ("these cases fail when an upgrade of bcrypt changes it") covers cases 1–3 too.

## Risks

- **A stored hash stops verifying**, which would lock users out: cases 1 and 3 run the hashes of 5.1.1 against the installed `bcrypt`, and fail if it changes.
- **The native module fails to load** in an app's image: the prebuilds cover glibc and musl on x64 and arm64 (probes); an image outside them builds from source through `node-gyp-build`, as with 5 when `node-pre-gyp` found no binary (not probed).

## Out of scope

- Rejecting passwords over 72 bytes or not well-formed: the backlog item *`BcryptPasswordHasher` reads only the first 72 bytes of a password*.
- Publishing 3.0.0: a session of its own (the `publish` skill).
- Root `CLAUDE.md` names `bcrypt` among the native modules that installs from two environments break. `bcrypt` 6 picks its prebuild when it loads, so it may no longer be one, except where an environment builds it from source (not probed); the rule holds through `mongodb-memory-server` either way, and the line stays.
